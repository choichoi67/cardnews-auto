# NOWA 템플릿 제작 작업 명세 및 리뷰 요청

작성일: 2026-10-16. 이 문서는 이번 세션의 사용자 요구와 개발 계획을 구분해 정리한다. 구현 완료 보고서가 아니다.

최신 구현·검증 상태와 실제 저장 규칙은 `template-studio-storage-and-validation.md`를 참조한다. 개발본 테스트 93개 및 브라우저 검증이 통과했으며, 운영 제작 작업이 남아 있어 운영 반영은 대기 중이다.

## 확정된 사용자 요구

- 기존 제작 화면 내부의 템플릿 탭을 분리한다. 사이드바 연결 상태 카드 바로 위에 독립적인 '템플릿 제작' 진입점을 둔다.
- PhotoCraft의 UI/UX와 관련 기능을 NOWA 템플릿 제작에 맞게 적용한다. 브러시 기능은 제외한다.
- PSD 및 디자인 템플릿 편집을 대상으로 한다. 기존 뉴스, 작업 기록, 로그, 산출물, API 키와 외부 서비스 연결을 보존한다.
- 템플릿 저장 진입점은 템플릿 제작 공간으로 통합한다.
- 채널마다 표지/본문/CTA 역할을 고정하고, 역할마다 활성 버전 1개를 사용한다. 이전 버전은 보관한다.
- 중복 저장, 채널 간 혼선, 저장 충돌과 기존 제작 기능의 회귀를 검토한다.
- REA로 설치된 PhotoCraft를 분석하고, OMC를 이용한 리뷰는 사용자가 지정한 이미 열려 있는 다른 에이전트에 요청한다.

PhotoCraft의 실제 화면과 동작을 확인한 뒤 세부 배치와 조작 방식을 확정한다. 모든 PSD 기능의 완전 재현을 전제로 하지 않는다. 미지원 효과는 사용자에게 명시하고 원본 보존 방법을 마련한다.

## 데이터 및 충돌 방지

1. 수정 작업은 `work/template-studio-development`에서 진행한다. 운영 DB와 인증 정보를 테스트 데이터로 쓰지 않는다.
2. 초안과 제작용 버전을 분리한다. 활성 버전은 변경 불가능한 스냅샷으로 저장하고 제작 작업에는 해당 버전을 고정한다.
3. 채널 ID와 역할을 검증한다. 다른 채널의 템플릿을 잘못 활성화하지 못하게 한다.
4. 저장 revision 및 활성 버전 비교로 오래 열린 화면의 덮어쓰기를 차단한다.
5. 동일 PSD 재업로드를 감지한다. 파일명이 같다는 이유로 기존 파일을 덮어쓰지 않는다.
6. 기존 템플릿은 목록/가져오기로 연결하고, 새 저장 경로 전환 전에 기존 UI·API 호출자를 점검한다.
7. 부분 저장 실패 시 기존 활성 버전이 유지되어야 한다. 경로 검증, 파일 크기 제한, 채널 범위 검증을 유지한다.
8. UI/API 변경 시 캐시 버전도 갱신한다. 기존 뉴스·작업·로그 화면이 정상 로드되는지 회귀 검증한다.

## 연결 코드 범위

- `webapp.py`, 기존 `index.html`, `app.js`, `ui.js`: 진입점, 라우팅, 기존 저장 UI/API 호출자 정리.
- `template-studio.html`, `template-studio.css`, `template-studio.js`, `studio-common.js`: 독립 편집 화면.
- `template_lab.py`, `template_lab_api.py`: PSD 분석, 초안/자산/편집 저장, 채널별 목록과 버전 API.
- `template_properties.py`, `template_primitives.py`, `template_runtime.py`: 속성 해석과 편집 결과 렌더링.
- `template_publication.py`, `production_policy.py`, `render.py`, `cli.py`: 활성 버전, 제작 정책, 버전 고정과 실제 산출물 연결.
- 관련 tests와 격리된 fixtures: 저장 충돌, 채널 격리, 실패 시 보존, 렌더링, 기존 기능 회귀 검증.

파일별 최종 변경 범위는 실제 호출 관계를 확인한 후 최소화한다.

## 진행 순서와 완료 기준

1. REA로 PhotoCraft 설치 파일과 확인 가능한 UI 동작을 분석한다. NOWA 소스는 일반 코드 분석으로 비교한다. 산출물: 기능 대응표, PSD별 부족 기능 목록.
2. 독립 화면과 레이어 편집을 개발 사본에서 완성한다. 산출물: 실제 PSD를 불러와 편집 가능한 화면.
3. 역할별 버전 저장과 제작 연결을 완성한다. 산출물: 채널별 표지/본문/CTA 활성 상태, 이전 버전 복원, 제작 버전 고정.
4. 사용자 지정 기존 에이전트에 OMC 리뷰를 요청한다. 수정 없이 먼저 결함 목록을 받는다. 우선순위: 데이터 보존 → 저장 충돌/채널 격리 → 제작 회귀 → PSD 표현 → UI.
5. 결함 수정 후 격리 테스트와 브라우저/실제 PSD 시각 검증을 통과한다. 백업과 복귀 경로를 확보한 뒤 필요한 코드만 운영에 반영한다.

완료 기준: 기존 데이터/설정 보존, 독립 진입점 정상 동작, 세 역할 활성 버전 관리, 충돌 차단, 실제 제작 및 기존 대시보드 정상, 주요 PSD 시각 차이 기록, 리뷰 지적 해결.

## 현재 상태와 남은 확인

- 운영 소스/UI는 이전 백업으로 복귀했고, 개발 중 코드는 별도 개발 폴더에 보관했다. 운영 DB를 과거 DB로 교체한 것은 아니다.
- 개발 사본에 독립 UI, 버전 관리 및 PSD 편집 확장 초안이 존재한다. 완료/배포 상태가 아니다.
- 직전 격리 테스트 결과는 23개 통과, 1개 실패다. 새 채널 기본 설정 fixture 문제를 해결해야 한다. 브라우저 및 실제 PSD 시각 검증은 미완료다.
- `C:/Program Files/PhotoCraft/photocraft.exe`를 찾았으며 REA open_binary로 x86_64 PE 실행 파일임을 확인했다. 기능/UI 분석 완료를 의미하지 않는다.
- OMC 4.15.10 설치를 확인했다. 연결된 에이전트 목록에는 현재 에이전트만 보인다. 발견한 Claude 팀 기록은 gajae-code 작업이며 사용자 지정 리뷰 대상인지 확인되지 않았다. 리뷰 요청은 아직 전송하지 않았다.
- CTA를 기존 장수에 포함할지 마지막에 추가할지와 이전 산출물 재제작 정책은 구현 전에 기존 동작을 확인해 명시해야 한다.
